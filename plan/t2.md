# T2: stability under shuffled options

Test design, written 2026-10-12 and committed before any T2 run. A change
after the commit goes into a new dated section at the end.

## Question

Does a decision change when nothing but the order of the options changes,
and how often does the same call give a different answer on another day?
A classifier that flips with the option order is not deciding on content.

## Why it matters

route1 measured accuracy once per arm. A customer who runs the same routing
every day needs the answer to be stable; an order effect also means the
accuracy of run 1 partly depends on an arbitrary choice (definition order of
the labels).

## Data

route1, MASSIVE de only: the 2,974 German requests of
`requests/route1/requests.jsonl` with their two questions (scenario out of
18, intent out of the intents of the gold scenario), 5,948 questions. English
and fast-decisions rows are left out to keep the test small; MASSIVE de is
the German home ground. Gold: `cases/route1/massive-de.jsonl`. No new data.

## Method

- Local LLM arms: the route1 call of `bench/run-local.mjs`, unchanged in
  every setting (raw prompt in the model's template, prefix `''`, options as
  letters, temperature 0, one token, top 20 logprobs, `num_ctx` 16384), run
  by `bench/t2/run_route.py`, because the workstation has no Node. The
  Python port is `bench/lib/route_local.py`; `bench/t2/test_route_port.py`
  (CI) checks that it builds byte-identical prompts and the identical seeded
  shuffle as the Node code for every template.
- GLiNER arm: the route1 call of `bench/run-gliner.py`, mode prompt, one
  question per call.
- Two passes per arm in one job, same model load: `plain` (options in
  definition order, the route1 order) and `shuffled` (the options of both
  questions in the order of `withShuffledOptions` with seed 1002, the seed
  `run-local.mjs` gives the shuffled run of `--runs 2`).
- Rows keep options and probabilities in definition order, so passes compare
  question by question.

## Metrics

- Primary: flip rate shuffled against plain (share of questions whose
  choice differs; an unanswered row is a flip).
- Secondary: flip rate plain against the committed route1 run 1 of
  2026-10-09 (the same call on a later day, run-to-run noise, which bounds
  how much of the order flip rate is noise); accuracy of both passes and the
  exact McNemar test between them.
- Bootstrap unit: the utterance (both questions together), 1,000 resamples,
  `default_rng(20261009)`, 95 % percentile intervals.
- Scorer: `bench/t2/score_t2.py t2`.

## Sanity gate

Internal check, since no published number exists: before the full jobs, the
plain pass of the port on the first 250 MASSIVE de requests (500 questions)
must agree with the committed route1 run 1 of the same arm on at least 99 %
of the choices, for `winnow-12b` and for `gliner2.5-multi-decide`. A miss
means the port or the runtime differs from route1, and the T2 and T9 jobs
(which depend on these two) do not start.

## Expected GPU time

About 80 minutes: 2 x 5,948 questions per arm at the route1 median latency
(Winnow-12B 89 ms, Gemma 4 12B 85 ms, Qwen3.8 27B 217 ms, GLiNER 14 ms),
plus model loads.
