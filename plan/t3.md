# T3: classic baseline on route1 MASSIVE

Test design, written 2026-10-09 and committed before any T3 run and before
any MASSIVE train row was read for this test. Roadmap row T3 of
`plan/ROADMAP.md`. A change to this design after the commit goes into a new
dated section at the end, never into the text above it.

## Question

How far does a cheap trained classifier get on route1 MASSIVE (scenario
and intent, German and English) when labelled training data exists? This
is the home ground of the new tool family `classic`: MASSIVE ships a train
split of 11,514 utterances per locale with the same 18 scenarios and 60
intents as the test rows of route1. The zero-shot arms (Jev, GLiNER Decide,
Winnow-12B) get no training data, so a classic lead is the expected result
and measures what labelled data buys, not which model is smarter.

## Model, fixed in advance

- Embeddings: `intfloat/multilingual-e5-base` from Hugging Face, revision
  `d128750597153bb5987e10b1c3493a34e5a4502a` (head of `main` on
  2026-10-09), licence MIT (card metadata, read 2026-10-09). Loaded with
  `sentence-transformers` (mean pooling as shipped in the model's
  sentence-transformers config), embeddings L2-normalised. Every text gets
  the prefix `query: `, as the model card says for using the embeddings as
  features ("linear probing classification").
- Classifier: scikit-learn `LogisticRegression(C=1.0, max_iter=2000)`,
  multinomial (solver lbfgs, the scikit-learn default for more than two
  classes), no class weights, no feature scaling beyond the normalisation.
- Two classifiers per locale, trained separately: scenario (18 classes)
  and intent (60 classes).
- No hyperparameter search, no dev split use, no look at the test rows
  before the run. C, max_iter and the prefix are the values above and stay
  so even if the result is poor.

## Data

- Source: MASSIVE 1.1,
  https://amazon-massive-nlu-dataset.s3.amazonaws.com/amazon-massive-dataset-1.1.tar.gz,
  the same tarball as `cases/route1/` (SHA-256
  `4cba5faa11c71437928e17cb1b9b3d8b8e727e7ea363a3a9a8045e19c0491577`,
  checked before use). Licence CC BY 4.0, attribution as in
  `cases/route1/README.md`.
- Training rows: partition `train` of `1.1/data/de-DE.jsonl` for German,
  `1.1/data/en-US.jsonl` for English, fields `utt`, `scenario`, `intent`.
  Expected 11,514 rows per locale; the runner records the count it found.
- Test rows: the frozen route1 requests (`requests/route1/requests.jsonl`,
  MASSIVE lines only), 2,974 per language, two questions each.
- The train split is not committed (it is large and anyone can rebuild it
  from the tarball). The runner records the tarball hash, the row count and
  a SHA-256 over the training rows it used in every result row
  (`train`), so the recipe can be repeated and checked.

## Arms

| arm | training data |
|---|---|
| `classic-e5-lr` | the full MASSIVE 1.1 train split of the same locale |
| `classic-e5-lr-10shot` | 10 training rows per class, drawn from the same split with a seeded generator (numpy `default_rng(20261009)`, per class a sample without replacement, a class with fewer than 10 rows keeps all). Drawn separately for the scenario classifier (10 per scenario) and the intent classifier (10 per intent). Shows how much of the result is the data. |

## How the questions are answered

Every route1 MASSIVE question is answered alone, as for the other arms.

- `scenario`: predict_proba of the scenario classifier over the 18 offered
  options, renormalised over the options (they are all 18 classes), choice
  = argmax.
- `intent`, scored like every other arm (oracle setup of route1): the
  intent classifier gives probabilities over all 60 intents; only the
  options the request offers (the intents of the gold scenario) are kept,
  renormalised, choice = argmax among them. This keeps the number
  comparable to the other arms, which see the same option list.
- Extra, flat 60-way intent: argmax over all 60 intents, stored per intent
  row as `choice_flat`. Reported next to the oracle number, never in its
  place. It is the honest end-to-end intent number of a router.
- An option the classifier has never seen in training (possible only for
  the 10-shot arm if a class is missing) gets probability 0; the runner
  stops if a test option is unknown to the full-data classifier.

Result rows use the route1 row format: `options`, `probs` (rounded to four
decimals), `choice`, `latency_ms` measured per question (embedding the
utterance plus predict_proba, one item at a time, batch size 1, after a
warm-up), `host: "local"`, `arm_version` with the model id and the
classifier, `arm_revision` with the Hugging Face revision, `runtime` with
the versions of Python, torch, sentence-transformers and scikit-learn and
the device (MPS or CPU on a Mac). Files:
`results/route1/<arm>/2026-10-09-run1.jsonl` (or the run date).

## Where it runs

On a Mac (Apple silicon), MPS when available, else CPU. A Python venv
outside the repository with `sentence-transformers` and `scikit-learn`
from PyPI; versions are recorded in every row and in the findings.

## Not run

- fast-decisions: the dataset publishes only the dev split, no train
  split, so there is nothing to train on. The classic cell of
  `route1-fastdec26-en` is `not_applicable` with that reason.
- pv1 and einv1: no labelled training data outside the test rows, so
  `not_applicable`.
- ex1 slot extraction: a trained slot tagger is possible (MASSIVE train
  has slot annotations) but is a different model, not this test. `open`.

## Scoring and the tool map

- `bench/score-route.mjs` scores the two arms like every other arm (acc,
  macro-F1, base, skill, exact McNemar against `jev`, p50 latency) and adds
  a table of the flat 60-way intent accuracy for arms whose rows carry
  `choice_flat`.
- `bench/toolmap.mjs` gets the family `classic` with its tools entry (name,
  maker, how it runs, licence). The map takes the family's best arm, as for
  every family. The `top_family` of a row and the `mcnemar_vs_top_p` of the
  three zero-shot families stay computed among those three, so no existing
  cell changes: the diff of `results/toolmap.json` is additions only. The
  classic cell carries `mcnemar_vs_jev_p` and its own test against that
  zero-shot top.
- `results/route1/findings.md` gets an addendum "Classic baseline" with
  the numbers against Jev.
